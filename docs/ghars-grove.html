رواه الترمذي وحسّنه — عن جابر بن عبد الله رضي الله عنه

The hadith is already the mechanic. Every tasbeeh plants one palm. So the counter isn't a number in a ring like the app's other four challenges — the counter is a grove, drawn palm by palm at first light. A daily challenge, goal 100, resetting at Cairo midnight like the rest.

الغَرْس

The signature — tap to plant

Tap anywhere on the grove. A sapling breaks the soil at the next slot in the front row, unfurls, and stands. When the front row fills, the grove steps back a row. Keep going to 25 — the grove completes, recedes to the horizon, and fresh soil opens up. Tap ~25 times in the demo to see it.

لماذا الغَرْس، لا العدّاد؟

The other four challenges all end in the same place: a number inside a progress ring. Here the hadith hands you a better one — a palm, planted. So the count is the grove, and the ring is gone.

Each palm is deterministic: height, lean, frond count and sway all come from a seeded RNG on its index, so palm #12 looks identical on every device. Drawn only with Paths, arcs and gradients — no blur — so it ports 1:1 to Compose Canvas. Never more than 25 on screen, so the cost is a constant.

البستان

One grove = 25 palms. Four groves = the day's goal.

The screen never draws more than 25 palms. The 25th bears dates and completes the grove; the next tasbeeh sends that grove receding into the tree-line on the horizon and breaks fresh soil in front. Nothing is erased — the day's work accumulates as distance. The score keeps climbing regardless, and resets at Cairo midnight like every other challenge.

التنفيذ

Implementation plan

A plain daily challenge — it clones istighfar exactly (Store + FirebaseClient + FirestoreMirror, orchestrated by the ViewModel; no repository). No new schema, no lifetime total, no rules change beyond one new subtree. Feature name: ghars (الغَرْس). Everything novel lives in the renderer.

1

Data & domain — no UI

mechanical clone · tests first
  • domain/GharsModels.kt — GHARS_DAILY_GOAL = 100, GHARS_GROVE_SIZE = 25, GharsDayStats, GharsLeaderboardEntry. Copy of IstighfarChallengeModels.kt.
  • data/ghars/GharsStore.kt — remote-baseline + pending-delta, keyed on the Cairo date. Same file as IstighfarChallengeStore with new keys.
  • data/ghars/GharsFirebaseClient.kt — writes ghars_challenge/{dateKey}/users/{uid}/count and /data; reads server-computed rank, participantCount, leaderboard.
  • FirestoreMirror.mirrorGharsUserDay(…) — dual-write, fire-and-forget. New collection ghars_challenge/{dateKey}.
  • ChallengeType.GHARS(id="ghars", dailyGoal=100) → the badge falls out of the existing ChallengeBadgeStore for free.
  • database.rules.json + firestore.rules — one new subtree, same shape as the istighfar block (aggregates read-only to the client).
  • Tests: GharsStoreTest — pending-delta flush, Cairo day rollover, previous-day back-flush.
2

The grove renderer

the only new thing
  • ui/ghars/GroveMath.kt — pure Kotlin, no Compose: mulberry32 seeded RNG, palmParams(index), band occupancy over CAPS = [7, 8, 10], slotX. Unit-tested for determinism.
  • The wrap: shown = if (n == 0) 0 else ((n - 1) % 25) + 1, groves = n / 25. At most 25 palms are ever drawn — the perf ceiling is a constant, not a function of the score.
  • ui/ghars/PalmGroveCanvas.kt — Compose Canvas. Only Path (quadratic), drawArc, drawOval, linear/radial Brush. No blur anywhere — haze and glow are radial gradients + alpha, so it ports 1:1 from the mockup and stays cheap. No ImageBitmap caching needed at 25 palms.
  • Three Animatables: sprout 620 ms (height eases out, fronds unfurl), soil burst 700 ms, grove-recede 1,200 ms. All skipped when the OS reports reduced motion.
  • The finished grove is not erased — it shrinks toward the horizon and joins a procedural tree-line whose density comes from groves. One cheap Path.
3

Screen, wiring, strings

  • presentation/GharsViewModel.kt + GharsUiState.kt; onScreenEntered / onScreenLeft flush behind a Mutex, exactly as istighfar does.
  • ui/GharsScreen.kt — the grove is the tap target (whole hero clickable, Role.Button); sand sheet below. ui/ghars/GharsDesignSystem.kt holds the palette as an internal object, matching the four existing design-system files.
  • ui/ghars/GharsLeaderboardSheet.kt + ManualTasbeehSheet.kt — copies of the istighfar pair.
  • Fonts: Aref Ruqaa + IBM Plex Sans Arabic into composeResources/font/. First custom fonts in the app — scope them to this screen only; don't retrofit the others yet.
  • di/AppModule.kt: two singles + one viewModel. App.kt: flag, PlatformBackHandler, nicknamePromptBlocked, when branch, callback — the same 5 edits every challenge needs.
  • Strings across all four locales in one pass: values/ (ar), values-en/, values-ur/, values-zh/.
4

Server & entry point

  • scripts/generate-stats.js — aggregate totalTodayGhars, participantCount, top-10 leaderboard, per-user rank; add the rank-1 FCM notification beside the dhikr and baqiyat ones.
  • ChallengesScreen.kt — the ChallengeItem card (accent #1F5C40, the only deep green in the row); ChallengesViewModel.kt — read today's community total.
  • Analytics: GHARS_SCREEN_VIEW, GHARS_TAP, OPEN_GHARS_CHALLENGE.

Phases 1 and 2 are independent — the renderer needs no backend and the store needs no UI, so they can run in parallel. Phase 1 is near-mechanical; budget the real time for phase 2.

القرارات

What I chose, and what I cut

Daily, like every other challenge

Score resets at Cairo midnight, same as dhikr / baqiyat / istighfar. Zero schema surprises — one new RTDB subtree, one new Firestore collection, no lifetime total, no new rule shape.

25 palms, hard ceiling

The canvas never draws a 26th. The score is unbounded; the drawing is not. That turns the renderer's cost into a constant and removes the perf risk entirely — no bitmap caching, no LOD, nothing to measure on a low-end device.

The wrap is a moment, not an erase

A hard clear at 25 would read as losing your work. Instead the finished grove recedes into the tree-line on the horizon and fresh soil opens in front. Still ≤25 palms drawn; the day's total is legible as depth. This replaces the confetti the other challenges fire.

Cut: the water channel

I drew a still قناة (the Islamic-garden water channel) and then killed it. Finicky code for a 40px strip that the grove didn't need. The accessory to remove before leaving the house.

Cut: a tending sim

"Agriculture" could mean watering / pruning / trees dying from neglect. I didn't build it — a reward tree doesn't die because you skipped a day. Say the word and I'll add slow maturation as a layer, which keeps the theology intact.
